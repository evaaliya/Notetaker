2. Ожидаемое поведение
Отправка напоминаний
В момент «время заметки минус интервал напоминания», если заметка активна, отправляется письмо.
Для каждого напоминания отправляется ровно одно письмо.
Уведомления в интерфейсе
Если приложение открыто в браузере, уведомление появляется в интерфейсе в тот же момент.
Уведомление отображается во всех открытых вкладках.
Уже показанное уведомление не появляется повторно после обновления страницы.
Поведение при активации и деактивации
Деактивированная заметка не отправляет напоминания.
При повторной активации до срока напоминания уведомления возвращаются.
При активации после истечения срока прошедшие напоминания не отправляются.
Изменение заметки и напоминаний
Изменение времени заметки или интервала напоминания переносит запланированные напоминания.
Удаление и восстановление
Удаление заметки отменяет её напоминания.
Восстановление из корзины возвращает напоминания, срок которых ещё не наступил.
Корзина автоматически очищается через 30 дней после удаления.
Повторяющиеся заметки и напоминания
Повторяющаяся заметка отправляет напоминание для каждого вхождения.
Изменение серии «начиная с этого дня» не затрагивает предыдущие вхождения.
Синхронизация между вкладками и устройствами
Если заметка открыта в двух вкладках или на двух устройствах, её состояние одинаково.
Изменения в одной вкладке или на одном устройстве становятся видны в другой вкладке или на другом устройстве без перезагрузки.
Календарь, список заметок и экран «Ближайшее» также обновляются без перезагрузки.
Одновременное редактирование
Если заметку одновременно редактируют с двух сторон, ни одно изменение не должно теряться молча.
При изменении версии второй пользователь должен увидеть уведомление о том, что версия заметки изменилась.
Часовые пояса
Время заметок отображается в часовом поясе пользователя.
Изменение часового пояса в настройках меняет отображение времени, но не фактический момент отправки напоминания.
Автоматическое обновление прошедших заметок
Когда время заметки проходит, она автоматически перемещается в раздел прошедших на экране «Ближайшее» без перезагрузки страницы.
Производительность поиска и списка
Поиск и фильтры работают по всем заметкам, а не только по загруженной или видимой части списка.
Несколько тысяч заметок должны открываться и прокручиваться без задержек.

## Технические риски

| Риск | Почему | Митигация |
|---|---|---|
| Touch vs scroll | Случайный drag на mobile | Long-press + min distance; drag не стартует от scroll |
| Agenda ≠ пиксельный таймлайн | Week/day — список hour-marks, не `DAY_HEIGHT_PX` | Drop на day-section / hour-row, snap к часу (минуты: 0 или сохранить старые — в D-NNN: **snap к `:00` часа цели** для week/day) |
| Месяц mobile + FC | FC touch DnD хрупкий | `longPressDelay`; e2e с Playwright touch; fallback — если FC не тянется, pointer-layer только для trash+day cell (остановиться и показать, если e2e падает) |
| Серии | Уже `scope=this` | Не менять API; e2e на override |
| Период + серии | API приближённый (`STATUS`) | UI честно использует API; в DECISIONS — без смены бэкенда |
| `from > to` | Пустой/странный список | Клиент: не применять / подсветка ошибки, если from > to |
| Границы TZ | Полуночь в user TZ ≠ UTC | Хелперы start/end of local day |
| Конфликт с FRONTEND/D-098 | Спека UI запрещала DnD вне month | Явное D-NNN + правка FRONTEND в том же этапе |
| Flaky e2e DnD | Уже был flake week-slot | Стабильные `data-testid`, `dragTo` с force только где нужно; при падении — стоп и отчёт причины |
