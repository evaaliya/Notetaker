## Что делает функция (по коду сейчас)

На `/capture/video` пользователь вставляет YouTube-ссылку → «Открыть» (IFrame API) → «Разобрать субтитры». Клиент зовёт `POST /api/extract/youtube`. Сервер (`youtube_captions.py`): парсит id (`youtu.be` / `watch?v=` / shorts/embed), через httpx ходит на youtube.com (watch → Innertube ANDROID `youtubei/v1/player` → timedtext), берёт дорожку (pref: ru/en/…, manual > asr), `captions_xml_to_text` склеивает XML/JSON3 **в обычный текст без таймкодов**. Дальше stub/OpenRouter → черновики; UI подтверждает → `POST /notes` с `source=video`, `source_url`, `source_ts=null`, `ai_generated=true`. Медиа не качаем. Ошибки по-русски: нет субтитров / ролик недоступен / YouTube недоступен (502). После D-072 нет формы «к секунде» и клика по таймкоду → seek.

Расхождение с п.4 твоего ТЗ: **таймкодов в UI и seek по клику сейчас нет** — поведение не буду возвращать молча. E2e спланирую под фактический поток (ссылка → подмена extract → конспект → заметка); seek — только если скажешь вернуть UI.

## Фактическое поведение (исправлено)

На `/capture/video` пользователь вставляет YouTube-ссылку → «Открыть» (IFrame) → «Разобрать субтитры». Клиент зовёт `POST /api/extract/youtube`. Сервер парсит id, через httpx/Innertube ANDROID тянет текстовую дорожку captions (ручные или ASR; без скачивания медиа), склеивает XML/JSON3 в обычный текст и прогоняет через stub/OpenRouter extract.

Ответ содержит `summary` и при английском источнике ещё `summary_ru` (та же структура конспекта). В модалке подтверждения для EN-пары пользователь выбирает **English (оригинал)** или **Русский (перевод)**; сохраняется одна заметка на выбранном языке. Для русского источника второй язык не предлагается. После выбора — «Подтвердить» → `POST /notes` с `source=video`, `source_url`, `source_ts=null`, `ai_generated=true`. Ошибки по-русски: нет субтитров / ролик недоступен / YouTube недоступен. Привязки к таймкодам нет **намеренно**: продукт — короткий конспект без таймингов.
