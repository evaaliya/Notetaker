## Диагностика (шаг 0) — готово

Коммит: `1a9c8e0` · запись **D-082**.

### Измерения (ролик `Ok6QdZHCcI8`, `openrouter/free`)

| Шаг | Pass 1 | Pass 2 |
|---|---|---|
| YouTube captions (watch+innertube+timedtext) | **7.5 с** | **7.0 с** |
| OpenRouter `_chat` | **53.7 с** | **182.0 с** |
| HTTP `POST /api/extract/youtube` | **29.2 с** · 200 | **67.2 с** · 200 |

Доказано: `httpx.Timeout(90)` — таймаут **между чанками**, не wall-clock: trickle 1 байт/20 с → ответ за **120 с** без ошибки. Поэтому 182 с при «timeout=90» — ожидаемо.

### Причина

1. Узкое место — **OpenRouter free** (переменная латентность), не субтитры (~7 с).
2. Один синхронный HTTP без прогресса; клиентский `fetch` без timeout/Abort.
3. Кэша субтитров нет; повторов нет; общего дедлайна нет.
4. «Второй быстрый из‑за кэша» **не подтверждён**: pass2 captions снова ~7 с, модель на pass2 была **медленнее**. Скорее лотерея free-пула. Кейс «~5 мин → непонятная ошибка» в этой сессии **не воспроизведён** — цифру 5 мин не выдумываем.

### Предлагаемые изменения

1. Job в БД + poll; cancel срывает этапы и не сохраняет результат.
2. Кэш captions по `video_id`; идемпотентность `(user, video)` для in-flight.
3. Wall-clock: captions 15 с, model 60 с, 1 retry, общий дедлайн.
4. Ошибки по-русски + «Повторить»; UI прогресс по шагам.
5. Аудит `api.ts` / WS / SMTP — таймауты, stale, double-submit без лишнего рефакторинга.
6. `POST /api/extract/youtube` sync оставляем (совместимость); UI → новые job-эндпоинты.
